# 异常检测 (anomaly-detection)

## 1. 适用边界

### 1.1 适用场景
- 业务指标异常（DAU / GMV / 转化率 / 留存 突变）
- 系统异常（CPU / 内存 / 网络 / 错误率）
- 安全异常（异常登录 / 数据外泄 / 异常访问模式）
- 质量异常（生产数据异常 / 测试失败率突增）
- 财务异常（异常交易 / 重复付款 / 退款激增）

### 1.2 不适用
- 已知错误模式（用规则引擎）
- 实时高频交易（< 1s 决策，用专门模型）
- 复杂事件关联（属 `event-correlation` skill）
- 战略异常（属 `trend-analysis` skill）

## 2. 异常类型分类

### 2.1 按数据维度

```
点异常（Point Anomaly）：
  单个数据点偏离正常
  例：某天 GMV 突然为 0

上下文异常（Contextual Anomaly）：
  数据点本身正常，但上下文异常
  例：冬天空调销量大增

集体异常（Collective Anomaly）：
  单个点正常，但整体模式异常
  例：连续 7 天 DAU 持续下降（每周都下降）
```

### 2.2 按异常方向

```
正向异常（业务好）：
  - GMV 突增 50%（可能是促销 / 异常订单 / 错误）
  - 需要快速识别 + 复盘（是真增长还是错误）

负向异常（业务坏）：
  - GMV 突降 30%（可能是故障 / 流量异常）
  - 需要立即响应 + 排查
```

### 2.3 按变化速度

```
突发异常：几分钟内变化（系统故障）
缓慢异常：几天到几周变化（业务下滑）
周期异常：特定时间出现（节假日 / 周末）
```

## 3. 检测算法选择

### 3.1 统计方法（基础）

```
Z-Score：
  - 偏离均值多少个标准差
  - 适用：近似正态分布
  - 阈值：|z| > 3

IQR（四分位距）：
  - Q3 + 1.5*IQR 或 Q1 - 1.5*IQR 之外为异常
  - 适用：非正态分布
  - 优点：简单直观

Grubbs 检验：
  - 检验单个离群点
  - 适用：小样本
```

### 3.2 时序方法（更准）

```
移动平均（MA）：
  - 偏离 N 天移动平均的程度
  - 适用：平稳序列

指数平滑（ES）：
  - 加权历史数据
  - 适用：趋势 + 季节性

STL 分解：
  - 季节 + 趋势 + 残差
  - 异常看残差部分

Prophet：
  - Facebook 开源
  - 适用：强季节性 + 节假日效应
```

### 3.3 机器学习方法（高级）

```
Isolation Forest：
  - 随机切分 + 异常易被隔离
  - 适用：高维数据
  - 优点：无需标注

One-Class SVM：
  - 学习正常数据的边界
  - 适用：异常稀少

AutoEncoder：
  - 神经网络压缩 + 重构
  - 重构误差大 = 异常
  - 适用：复杂模式

LSTM：
  - 时序预测
  - 实际偏离预测 = 异常
  - 适用：复杂时序
```

### 3.4 算法选择决策树

```
Q1：数据维度
  - 1 维 → 统计方法
  - 多维 → 机器学习

Q2：数据量
  - < 1000 点 → Grubbs / IQR
  - 1000-10000 → MA / ES / STL
  - > 10000 → ML / LSTM

Q3：季节性
  - 强季节 → STL / Prophet
  - 弱季节 → MA / ES

Q4：可解释性需求
  - 高 → 统计 / STL
  - 低 → ML / LSTM
```

## 4. 阈值校准

### 4.1 阈值类型

```
固定阈值：基于业务知识
  例：CPU > 90% 告警
  适用：硬性 SLA

动态阈值：基于历史数据
  例：P95 * 1.5
  适用：浮动正常范围

混合阈值：基础 + 动态调整
  例：基础 90% + 动态 * 1.2
  适用：硬性 + 浮动兼顾
```

### 4.2 校准方法

#### 历史回测
```
取过去 30 / 90 天数据
试不同阈值（z=2.5 / 3 / 3.5）
计算：召回率 + 误报率 + 准确率
选择：业务可接受的平衡点
```

#### 业务标注
```
标注一批已知异常（如事故）
用不同阈值检测
看哪个阈值捕获已知异常最多 + 误报最少
```

#### 持续优化
```
每周回顾：
- 误报（实际正常） → 阈值调严
- 漏报（实际异常） → 阈值调宽
- 持续调整至最优
```

## 5. 误报管理

### 5.1 误报来源

```
阈值过严：太敏感
季节性忽视：节假日 / 周末 模式不同
促销 / 活动：故意制造异常
数据问题：数据延迟 / 错误
```

### 5.2 误报率目标

```
P0 异常：误报率 < 5%（关键告警）
P1 异常：误报率 < 15%
P2 异常：误报率 < 30%
```

### 5.3 降低误报

```
1. 加入季节性：节假日 / 周末不同阈值
2. 持续基线：用滚动窗口而非全局
3. 多指标联合：单一指标易误报，多指标交叉验证
4. 静默期：同一异常不重复告警
5. 人工标注反馈：让系统学习
```

## 6. 异常响应

### 6.1 响应流程

```
异常检测
  ↓
自动分类（级别 + 类型）
  ↓
自动通知（值班 + 升级）
  ↓
人工确认（值班）
  ↓
根因分析
  ↓
短期修复
  ↓
长期改进
  ↓
复盘（写入知识库）
```

### 6.2 根因分析（RCA）

```
5-Why（5 个为什么）：
  GMV 突降 30%？
  → 因为订单量下降
  → 因为支付失败率高
  → 因为支付服务故障
  → 因为部署了新版本引入 bug
  → 因为上线流程缺少回滚预案
```

### 6.3 响应级别

| 级别 | 响应时间 | 通知 |
|------|----------|------|
| P0 | 5min | 全员 + 高管 |
| P1 | 30min | 值班 + 主管 |
| P2 | 4h | 值班 |
| P3 | 24h | 邮件 |

## 7. 异常分类与归档

### 7.1 分类维度

```
类型：业务 / 系统 / 安全 / 质量 / 财务
方向：正向 / 负向
频率：单次 / 周期 / 持续
影响：用户数 / 营收 / 品牌
根因：技术 / 业务 / 外部 / 人为
```


## 10. 反模式

- ❌ 只看指标不看上下文（季节性误判）
- ❌ 单一指标告警（噪音大）
- ❌ 阈值拍脑袋（误报漏报）
- ❌ 检测到异常不归档（重复踩坑）
- ❌ 只做检测不做根因（治标不治本）
- ❌ 高频监控无静默期（告警风暴）
- ❌ ML 模型上线不监控（漂移无人发现）
