# 竞争分析 (competitor-analysis)

## 1. 适用边界

### 1.1 适用场景
- 新产品/新业务线启动前的市场定位
- 年度/季度战略规划需要竞品输入
- 竞品重大发布（融资/产品/定价）应对
- 定价决策（避免定价过低/过高）
- 差异化营销文案输出

### 1.2 不适用
- 行业宏观分析（属 `trend-analysis` skill）
- 用户需求调研（属 `user-research` skill）
- 技术选型（属 `solution-design` skill）

## 2. 竞品识别四象限

### 2.1 识别框架（按替代关系）

```
直接竞品（同一需求 + 同一客群 + 同一价格带）  ← 核心
  例：Slack ↔ Teams

间接竞品（同一需求 + 不同形态）              ← 次要
  例：Slack ↔ 邮件

潜在竞品（不同需求但可能延伸）              ← 监控
  例：Notion ↔ Slack（都在抢协作场景）

替代品（完全不同但替代使用）                ← 边缘
  例：Slack ↔ 面对面会议
```

**实操**：至少识别 3-5 个直接竞品 + 5-10 个间接/潜在竞品

### 2.2 竞品清单数据源

```
- 行业报告（Gartner / IDC / Forrester / 艾瑞）
- 投资人视角（CB Insights / IT 桔子 / Crunchbase）
- 客户视角（G2 / Capterra / 知乎 / Reddit）
- 搜索引擎（搜索核心需求词，看 top 结果）
- 应用商店（按品类 + 关键词搜）
- 自有数据（用户流失访谈中提到的替代品）
```

## 3. 信息收集方法（4 类来源）

### 3.1 公开数据（最易获得）

```
- 公司官网 + 定价页 + 功能页
- 产品 Demo / 试用
- App Store / 应用商店评论
- 招聘网站（看技术栈 / 团队规模 / 重点方向）
- 财报（上市公司）
- 融资事件（Crunchbase / IT 桔子）
- 专利 / 论文（Google Patents / arxiv）
```

### 3.2 用户口碑

```
- G2 / Capterra 评论（按功能 + 行业筛选）
- Reddit / Quora / 知乎 / V2EX
- 微博 / 小红书 / 公众号（用户自发讨论）
- 自有用户调研（流失用户访谈）
```

### 3.3 第三方数据

```
- SimilarWeb（流量数据）
- Sensor Tower（App 下载量）
- 蝉妈妈 / 飞瓜（短视频数据）
- 5118 / 站长之家（SEO 数据）
```

### 3.4 实战情报

```
- 试用竞品（注册账号、走完核心流程）
- 参加竞品 webinar / 发布会
- 与竞品前员工/客户交流
- 反向工程（分析竞品的 API / 数据流）
```

**注意**：避免不正当手段（爬虫频率控制、不爬隐私数据、不假装用户）

## 4. 对比框架

### 4.1 功能对比矩阵（基础）

```
维度        自家    竞品 A   竞品 B   竞品 C
核心功能 1   ✓✓✓    ✓✓      ✓✓✓     ✓
核心功能 2   ✓✓     ✓✓✓     ✓       ✓
核心功能 3   ✓✓✓    ✗       ✓       ✓
价格         $$$     $$      $$$     $
目标客群     SMB     Enterprise   Mid-market   Enterprise
```

### 4.2 SWOT 分析（战略层）

```
S - Strengths（自身优势）
W - Weaknesses（自身劣势）
O - Opportunities（市场机会）
T - Threats（市场威胁）

矩阵组合策略：
SO: 用优势抓机会（进攻）
ST: 用优势避威胁（防御）
WO: 补劣势抓机会（投资）
WT: 避劣势避威胁（退守）
```

### 4.3 战略群组分析（Strategic Group）

把竞品按 2 个关键维度分组：
```
        高价格
          │
   ┌──────┼──────┐
   │  A    │  B   │  ← 高客单价
   │       │      │
低 ├───────┼──────┤ 高
客均│  C    │  D   │ 客均
营收│       │      │ 营收
   │       │      │
   └───────┼──────┘
          │
        低价格
```

**意义**：识别自己所在象限 + 空白象限（潜在机会）

## 5. 差异化定位

### 5.1 定位三要素

```
对谁（Target Customer）  +  提供什么（Value Prop）  +  比对手强在哪（Proof）
```

**公式**：
```
[产品名] 是 [品类] 中，专注 [细分客群] 的 [独特价值]，区别于 [竞品] 的 [关键差异]。
```

**例**：
- Slack: "面向企业的协作 IM，强调整合（vs 邮件分散）"
- Notion: "面向小团队的 all-in-one 工作空间（vs 多工具分散）"
- Linear: "面向工程团队的高效 issue 跟踪（vs Jira 慢）"

### 5.2 定位验证（4 问）

```
1. 用户能用 5 秒重复你的定位吗？
2. 竞品能用 5 秒反驳你的定位吗？
3. 你的定位指向具体功能吗？
4. 你的销售/营销话术与定位一致吗？
```

任何 1 个答「否」，重新审视。

## 6. 动态监控

### 6.1 监控频率

| 监控项 | 频率 | 来源 |
|--------|------|------|
| 竞品融资 / 重大发布 | 实时 | 36Kr / Crunchbase / 公司公告 |
| 竞品定价变化 | 季度 | 官网定价页 |
| 竞品功能更新 | 月度 | 官网 changelog / 媒体 |
| 竞品用户评价变化 | 季度 | G2 / Capterra |
| 竞品战略调整 | 半年度 | 财报 / 公开演讲 |

### 6.2 告警机制

```
P0: 竞品发布同类核心功能（48h 内必须响应）
P1: 竞品融资 > 1 亿美元（1 周内评估）
P2: 竞品定价大幅调整（2 周内评估）
P3: 竞品高管变动 / 战略调整（季度复盘）
```

## 8. 反模式

- ❌ 只看直接竞品，忽略间接/潜在
- ❌ 只看功能不看商业模式
- ❌ 信息收集没有 source 标注（无法验证）
- ❌ SWOT 没有数据支撑（凭感觉写）
- ❌ 定位与产品实际能力不符（自嗨）
- ❌ 一次性分析后不再更新（竞品在动，你在停）

## 9. 自我审计清单

- [ ] 是否识别 ≥ 5 个直接/间接竞品
- [ ] 每个竞品是否有 source-backed 信息（不是道听途说）
- [ ] 是否有功能对比矩阵 + SWOT
- [ ] 定位是否能 5 秒复述
- [ ] 是否有动态监控机制
- [ ] 分析是否标注数据来源 + 日期

如有任何一项未达，**不要**输出 "竞争分析完成" 结论。
