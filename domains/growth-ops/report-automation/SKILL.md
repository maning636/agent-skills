# 报表自动化 (report-automation)

## 1. 适用边界

### 1.1 适用场景
- 定期报表自动化（日报 / 周报 / 月报 / 季报 / 年报）
- 董事会 / 投资人报表
- 客户报表（SaaS 类）
- 合规报表（财务 / 安全 / 隐私）
- 营销报表（活动 / 渠道 / ROI）

### 1.2 不适用
- 一次性深度分析（属 `data-analysis` skill）
- 实时大屏（属 `real-time-monitoring` skill）
- 探索性数据分析（属 `exploratory-analysis` skill）

## 2. 报表分类

### 2.1 按时间维度

| 类型 | 频率 | 受众 | 重点 |
|------|------|------|------|
| 日报 | 每天 | 运营 + 业务 | 当日异常 + 趋势 |
| 周报 | 每周 | 业务 + 管理层 | 周环比 + 累计 |
| 月报 | 每月 | 管理层 | 月度总结 + 趋势 |
| 季报 | 每季 | 高管 + 投资 | 季度战略复盘 |
| 年报 | 每年 | 董事会 + 投资 | 年度总结 + 展望 |

### 2.2 按受众维度

```
执行层（运营）：
  详细数据 + 当日行动项
  例：昨日转化率 5.2% (+0.3%)

管理层（总监）：
  趋势 + 异常 + 决策建议
  例：本月转化率 5.2%（行业 4.8%）

战略层（CEO / 董事会）：
  KPI + 战略进展 + 风险
  例：Q3 营收超预算 8%，核心增长来自 X
```

### 2.3 按内容维度

```
业务报表：营收 / 用户 / 转化 / 留存 / 客单价
运营报表：DAU / 活动参与 / 工单 / 满意度
财务报表：营收 / 成本 / 利润 / 现金流
技术报表：可用性 / 性能 / 故障 / SLA
人事报表：人数 / 入离职 / 培训 / 绩效
合规报表：合规事件 / 培训完成率 / 审计
```

## 3. 报表模板设计（5 段式）

### 3.1 标准结构

```
1. 摘要 (TL;DR)
   - 3-5 条关键结论
   - 异常事件
   - 行动项

2. 核心 KPI
   - 表格 + 趋势图
   - 与目标对比
   - 与上期对比

3. 详细数据
   - 按维度拆分（地区 / 产品 / 客群）
   - 异常细分
   - 同比环比

4. 异常与风险
   - 异常事件列表
   - 原因分析
   - 应对措施

5. 行动项
   - 本期行动
   - 下期计划
   - 责任人
```

### 3.2 模板版本管理

```
模板文件：
  - 1.0 → 1.1 → 1.2（语义化版本）
  - 重大变更：主版本升级（如加新板块）
  - 小改进：次版本升级（如调结构）
  - 修正：修订版本（如改数字）

存储：
  - Git 仓库
  - Markdown / Notion / Confluence
  - 每次变更要 commit + 写 changelog
```

## 4. 数据提取自动化

### 4.1 数据源分类

```
数据库：
  - PostgreSQL / MySQL / MongoDB
  - 直接 SQL 查询

API：
  - 内部服务 API
  - 外部 SaaS API（Stripe / HubSpot / GA4）

文件：
  - CSV / Excel
  - 共享盘 / S3

事件流：
  - Kafka / Kinesis
  - 实时聚合
```

### 4.2 提取方式

```
直接查询：
  - 写 SQL/API 拉数据 → 存结果
  - 适合：数据量小 + 实时

ETL 管道：
  - 抽取 → 转换 → 加载
  - 适合：定期大批量
  - 工具：Airflow / Dagster / Prefect

数据仓库：
  - 集中存储 + 维度建模
  - 适合：跨数据源整合
  - 工具：Snowflake / BigQuery / Redshift
```

### 4.3 数据校验

```
完整性：
  - 数据条数是否合理
  - 关键字段是否为空

准确性：
  - 与上一期是否连续
  - 与其他数据源是否一致

及时性：
  - 数据是否已更新到最新
  - 延迟是否可接受
```

## 5. 报表生成

### 5.1 生成方式

```
手动生成：
  - 适合：复杂分析 + 一次性报表
  - 工具：Excel / Google Sheets

半自动：
  - 模板 + 数据注入
  - 工具：Word 模板 + Mail Merge / Google Docs 模板

全自动：
  - 数据 → 模板 → 输出
  - 工具：Jupyter / R Markdown / Quarto / Retool
```

### 5.2 推荐技术栈

```
小团队（< 10 人）：
  - Google Sheets + Apps Script
  - Notion Database + Automation

中型团队（10-100 人）：
  - Metabase + Scheduled Reports
  - Retool / Internal.io

大团队（> 100 人）：
  - BI 工具（Tableau / Power BI / Looker）
  - 数据仓库 + 自动化管道
```

### 5.3 报表格式

```
HTML：
  - 适合：邮件 + 网页查看
  - 优点：可视化好
  - 缺点：难以二次编辑

PDF：
  - 适合：正式发布（董事会 / 客户）
  - 优点：格式稳定
  - 缺点：不易修改

Excel / Sheets：
  - 适合：详细数据 + 二次分析
  - 优点：灵活
  - 缺点：版本难控

Markdown：
  - 适合：内部分享 + 协作
  - 优点：易追踪变更
  - 缺点：可视化弱
```

## 6. 分发渠道

### 6.1 多渠道分发

```
邮件：
  - HTML / PDF 附件
  - 订阅 + 自动发送
  - 工具：Mailchimp / SendGrid / 内部邮件系统

IM 通知：
  - 钉钉 / 飞书 / 企微机器人
  - 适合：摘要 + 链接

存储归档：
  - 云盘 / Wiki / Notion
  - 适合：历史回溯

实时推送：
  - 看板（实时刷新）
  - 适合：监控类
```

### 6.2 分发策略

```
管理层：
  - 周报：周一 8:00 邮件 + IM 摘要

执行层：
  - 日报：每天 9:00 IM 通知 + 详细看板

客户：
  - 月报：每月 1 号邮件 PDF
  - 实时：客户专属看板

合规：
  - 季报：季后 10 天内提交
  - 年报：年后 30 天内提交
```

## 7. 异常处理

### 7.1 数据异常

```
缺失数据：
  - 备用数据源
  - 标记"待补"
  - 通知责任人

数据错误：
  - 校验规则触发
  - 立即停止发布
  - 修复后再发

延迟到达：
  - 标记"延迟"
  - 推迟发布或延用上一期
```

### 7.2 异常升级

```
P0：数据错误 + 影响决策
P1：数据缺失 + 影响判断
P2：数据延迟 + 不影响判断
```

## 8. 质量控制

### 8.1 三道关卡

```
生成前：
  - 数据源校验
  - 模板版本核对

生成后：
  - 数据合理性检查
  - 格式 + 链接测试

发布前：
  - 双人复核（关键报表）
  - 主管审批
```

### 8.2 报表质量指标

```
准确性：与原始数据 100% 一致
及时性：规定时间 ± 30 分钟内发布
覆盖率：100% 受众都能收到
可读性：受众能在 5 分钟内找到所需
互动率：被点击 / 分享次数
```

## 10. 反模式

- ❌ 每份报表都用 Excel 手工（无法自动化）
- ❌ 数据来源不清晰（无法验证）
- ❌ 模板没有版本管理（多次改版混乱）
- ❌ 没有数据校验（错误数据发布）
- ❌ 分发渠道单一（受众覆盖不全）
- ❌ 报表过多（淹没重点）
- ❌ 报表过简（缺少深度）
- ❌ 不做回顾（无法改进）

## 11. 自我审计清单

- [ ] 报表是否分类（时间 / 受众 / 内容）
- [ ] 模板是否有 5 段式结构
- [ ] 模板是否有版本管理
- [ ] 数据源是否清晰 + 校验规则
- [ ] 生成方式是否自动化（至少半自动）
- [ ] 分发渠道是否覆盖目标受众
- [ ] 异常处理是否有 SOP
- [ ] 质量是否有三道关卡

如有任何一项未达，**不要**输出 "报表自动化完成" 结论。
