# 第 8 关 · 上线前四审

> 原理见《Vibe Coding》系列第 8 章 ｜ 产物: `.vibe/review.md` ｜ 过关: `gate.mjs check 8`
> 定位：AI 是过度自信的初级开发，用户是技术负责人。**钱/数据/对外发送的代码，这关一步不能省。**

## 陪跑流程

1. **用干净上下文审**（自己审自己写的代码有偏爱）：spawn 一个子 agent 执行 ① 的审查任务；没有子 agent 能力就让用户新开一个对话贴 ① 跑。
2. 审出的问题按严重度排序 → 该修的用 ② 补防御（一类一类修，别一次全改）→ 修完把"已处理项"落 review.md 四段（每段至少一条 `- [x]`）。
3. **幻觉依赖核查**：跑 `node scripts/slopcheck.mjs --cwd <项目>`——自动核对 package.json 全部依赖在 npm registry 的真伪（404 = 疑似幻觉包，别装）；非 npm 生态手动去官方 registry 核。
4. 出错代价最大的 1-3 条路径**亲手走异常分支**，记进「关键路径手测记录」→ `gate check 8`。
5. 力度分配：涉钱/删数据/对外发送/隐私的代码四审全过 + 亲手测；纯展示只读的部分 AI 扫一遍你扫一眼就够。

## Prompt ①（给子 agent 的审查任务）

```
把这个项目当成上生产前的 review。上下文：
需求：<<注入 .vibe/vdf.md>> ｜ 架构与契约：<<注入 .vibe/blueprint.md>>
按四类逐一排查，列出所有问题并按严重程度排序，每条说明不修会在什么情况下出事：
1. 安全：SQL/命令/prompt 注入、XSS、硬编码密钥、越权（改 id 能否看别人数据）、依赖是否真实存在
2. 边界：空输入、超长、非法、越界，尤其没设上限的用户输入
3. 逻辑：并发重复（连点两次会怎样）、静默失败、幂等缺失
4. 性能：N+1 查询、循环里调外部 API/DB、常查字段缺索引
只报问题不改代码。
```

## Prompt ② 补防御（逐类修）

```
针对刚才审出的 [某一类] 问题，逐条给最小修复。
一类修完我确认，再修下一类。别顺手重构无关代码。
每修完一条，用一行"改了哪、怎么防"的格式给我——我要记进 review.md。
```

## Prompt ③ 异常路径测试

```
针对这几条出错代价最大的路径：[列出，如"付款中断/连点优化/超长输入"]
生成异常测试（或给我手测步骤清单）：空输入、超长、并发重复、外部接口失败。
```

## 过关前自查

- review.md 里的 `- [x]` 是"改了哪、怎么防"的具体动作，不是"已检查"三个字
- 新依赖都去 registry 核过真伪了吗？（slopsquatting 是真实攻击面）
