# 第 4 关 · 动手做第一版

> 原理见《Vibe Coding》系列第 4 章 ｜ 产物: `.vibe/build-log.md` ｜ 过关: `gate.mjs check 4`（会查 .git 存在）

## 陪跑流程

1. **先开 Git**（gate 机判项——改坏了没得退，这条不商量）。
2. 核心循环：小步生成 → 立刻测 → 具体反馈。一次只做一小块，每块能跑就 commit。
3. 报错走 ③；调不动就回退重来，别死磕（`git reset --hard` / 新开对话带 VDF 重说）。
4. 跑通后用 ④ 验收清单逐条勾，填 build-log.md → `gate check 4`。

## Prompt ① 出第一版（先方案后动手）

```
这是我的需求：<<注入 .vibe/vdf.md>>
先别写代码。先给一份方案：要做哪些部分、分几步做、用什么技术栈，让我确认。
我点头后从第 1 步开始，一次只做一小块，每做完一块告诉我怎么运行看效果。
严格守边界段——里面写了"不做"的东西，一行都不要写。
```

## Prompt ② 具体反馈

```
刚才那版我跑了，问题是：[具体说哪里不对，比如"提交按钮太小、没居中、点了没反应"]
只改这几个点，别动其它已经对的地方。改完告诉我重新运行看哪里。
```

## Prompt ③ 报错帮调

```
报错了。完整报错信息（整段，别只贴最后一行）：[粘贴]
出错的文件/代码：[贴上]。我期望它本来应该：[描述]
先分析原因，再给最小修复，别大改。定位不了就先加日志看中间值。
```

## Prompt ④ 验收清单（挪自第 3 章：VDF → 可勾的验收表）

```
根据这份 VDF：<<注入 .vibe/vdf.md>>，生成一张验收清单。
每条用"当我[做某操作]，应该[看到/得到某结果]"格式，覆盖正常流程、边界、失败处理。
我逐条勾；没过的就是下一轮要改的。
```
