# 第 16 关 · 第一笔收款（终点）

> 原理见《Vibe Coding》系列第 16 章 ｜ 产物: `.vibe/payment.md`「第一笔收款」段 ｜ 过关: `gate.mjs check 16`
> 第一笔验证的不是产品好不好，是"有人愿意为它掏钱"这件事真的成立。9.9 也算，"成立"才重要。

## 陪跑流程

1. 收不到钱先定位（①）：卡"看到→试用"是价值没讲清（回落地页第一屏）；卡"试用→付费"最常见——缺"现在就买的理由"或缺信任。
2. 对差一脚的人用 ②：限时/退款承诺/正好戳中他亲口说过的痛，三选一发力。主动去私聊最可能买的那个人，别干等。
3. **收到第一笔立刻问"你为什么买"**——最被低估的高杠杆动作，用 ③ 复盘。金额/来源/原话落 payment.md「第一笔收款」段 → `gate check 16`。
4. gate 过了跑 `state.mjs advance` → 毕业 🎉。然后按 ③ 的画像去找第十个一样的人——第一笔是偶然，第十笔是规律，中间隔的就是这次复盘。

## Prompt ① 转化漏斗诊断

```
在收第一笔钱，卡住了。数据：来了 [X] 人 → [Y] 人试用 → [Z] 人付费。
产品与价格：<<注入 .vibe/pricing.md 的「模型与价格」段>>
冷启动现状：<<注入 .vibe/gtm.md>>
判断卡在哪一环（看到→试用 还是 试用→付费）、最可能的原因，
针对这一环给 3 个具体改法，按见效快慢排序。
```

## Prompt ② 临门一脚文案（工具型）

```
有个用户试用了但没买。产品与价格：<<注入 .vibe/pricing.md 的「模型与价格」段>>
他犹豫的点：[你观察到的，如"觉得贵/不确定有用/怕白花钱"]
写一条私聊或弹窗文案促成这一单：用限时或退款承诺降低他的风险；
把产品和他具体的痛对上，别泛泛夸；像真人说话，不油腻不逼单。
```

## Prompt ③ 第一笔复盘

```
刚收到第一笔付款。买家信息：<<注入 .vibe/payment.md 的「第一笔收款」段>>
1. 从"为什么买"的原话提炼买家画像（他是谁、最痛什么、为什么选我）
2. 推断哪句卖点真正打动了他，落地页/文案该往哪改
3. 列出去哪还能找到 5-10 个和他一样的人（对照 gtm.md 的有效渠道）
```
