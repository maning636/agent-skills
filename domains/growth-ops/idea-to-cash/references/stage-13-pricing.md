# 第 13 关 · 定价

> 原理见《Vibe Coding》系列第 13 章 ｜ 产物: `.vibe/pricing.md` ｜ 过关: `gate.mjs check 13`
> 底层逻辑一句话：**价值定价，不是成本定价**——AI 时代开发成本趋近零，按成本定价 = 定到地板。

## 陪跑流程

1. 三问先答（给谁 / 替代方案花多少 / 省下多赚多少）——直接引用 direction.md 已有答案，别重问。
2. 用 ① 落成具体数字（首发价 + 正式价 + 涨价节点，宁可偏高再降、别定低了想涨）。
3. 用 ② 出锚点方案（起步单一买断价也要写明"暂不拆档"及理由）。
4. 用 ③ 准备验证——**预售真付钱才是证据，口头"会买"不算**。全部落 pricing.md → `gate check 13`。
5. 模型选择纪律：起步别上来就 freemium（免费转付费均值仅约 3.7%）。

## Prompt ① 三问落数字

```
帮我给产品定第一个价。定价三问的答案：
<<注入 .vibe/direction.md 的「具体的人」「切换理由」段 + Q5 算账段>>
请：
1. 给一个首发价和一个正式价（都用 9 结尾），说清为什么落在这个区间
2. 按"替代方案价是上限、找到用户几乎不用犹豫的点"解释这个价的心理账
3. 给一个涨价节点：什么信号出现时涨、涨到多少
把结果写进 .vibe/pricing.md 的「定价三问」「模型与价格」两段。
```

## Prompt ② 三档 + 锚点

```
我的产品 <<注入 .vibe/vdf.md 的 V 段>>，最想卖出去的价格是 [X 元]。
按锚点法设计三档：基础/主推/尊享，主推放中间、最高档当锚；
每档写包含什么、价格（9 结尾）、一句话卖点；明说哪档是"诱饵"、它存在的唯一目的。
如果起步其实该只用一个买断价，直接说——把结论写进 pricing.md「锚点」段（不拆档要写理由）。
```

## Prompt ③ 支付意愿验证话术

```
我要把价格 [X 元] 发给 5 个目标用户验证。帮我：
1. 写一段自然的私聊话术，问出"这个价你会买吗、贵不贵"，别像发问卷
2. 给"弦外之音"判读表：一口说"好便宜" / 皱眉但愿意买 / 客气地沉默，各说明该怎么调
3. 提醒哪些回答不算数——嘴上"会买"是客套，真付钱的预售才是证据
验证方式和结果写进 pricing.md「验证计划」段。
```
