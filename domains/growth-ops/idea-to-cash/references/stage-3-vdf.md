# 第 3 关 · VDF 需求表达

> 原理见《Vibe Coding》系列第 3 章 ｜ 产物: `.vibe/vdf.md` ｜ 过关: `gate.mjs check 3`

## 陪跑流程

1. 用 ① 把用户的一句话想法补成结构化 VDF（缺的地方标【需要确认】让用户答，不替他拍板）。
2. 写进 vdf.md 后跑 ②「写码前反问」把歧义磨干净——AI 问出的问题越具体越好，答案回填 VDF。
3. `gate check 3` 过了才进第 4 关动手。**D 段必须真实样例，禁止 {占位符}；边界至少 3 条**——gate 会机判这两条。

## Prompt ① 想法 → VDF

```
你是需求架构师。基于已验证的方向：<<注入 .vibe/direction.md>>
把要做的第一版整理成 VDF 四段，直接按 .vibe/vdf.md 的模板结构输出：
V 场景（谁/什么情况下用/用完拿到什么）
D 数据（一个真实输入样例 + 一个期望输出样例 + 映射——用真实数据，不许 {占位符}）
F 操作流程（1-2-3 路径 + 每步反馈 + 失败怎么办）
边界（至少 3 条"故意不做什么"）
凡是只能猜的地方，别替我拍板——用【需要确认】标出，列成问题问我。
```

## Prompt ② 写码前反问（最高杠杆的一步）

```
这是我的需求：<<注入 .vibe/vdf.md>>
先别写代码。做两件事：
1. 一段话复述你对需求的理解，让我确认没跑偏。
2. 列 3-5 个最影响结果的歧义点逐个问我——只问"答案会改变你怎么写"的问题。
我逐个回答后，把答案整合回 VDF 对应段落。
```

判断：它一个问题都问不出就开写——要么 VDF 已够清楚，要么它在硬猜。把它问出的问题补回 VDF，比收下它猜的版本靠谱。

## 过关前自查

- D 段拿给一个不懂技术的人看，他能想象出最终产物长什么样吗？
- 边界少于 3 条 = 还没想清楚不做什么（gate 会拦）
