# 第 12 关 · 内网访问

> 原理见《Vibe Coding》系列第 12 章 ｜ 产物: `.vibe/launch.md`「内网访问」段 ｜ 过关: `gate.mjs check 12`（form_factor=internal）

## 陪跑流程

1. 判断只有一条：**这东西的用户是不是只有你和同事？是 → 别上公网**（省备案省服务器省攻击面）。
2. 按"人在哪"选方案（①）：同一办公室 → 局域网 IP 直连；异地长期 → Tailscale 私有网络（常开、安全）；临时给外部看一眼 → ngrok/Cloudflare Tunnel（**用完必关**）。
3. 配置走 ②（必须带访问控制）。红线：**私有网络是常开的，公网隧道是临时的**；绝不拿隧道暴露 SSH/数据库/后台。
4. 落 launch.md「内网访问」段 → `gate check 12`。之后每次开过临时隧道，收工前跑 ③。

## Prompt ① 选内网方案

```
内部工具：<<注入 .vibe/vdf.md 的 V 段>>；用的人 [几个/同不同办公室/要不要异地]。
判断用哪套：局域网直连 / Tailscale 私有网络 / 临时公网隧道？说理由并给配置步骤。
提醒我哪些东西根本不该上公网。结论写进 .vibe/launch.md「内网访问」段的「方案」行。
```

## Prompt ② 配置 + 访问控制

```
用 [Tailscale / Cloudflare Tunnel / ngrok] 让我 [异地长期 / 临时] 访问内网的 [某服务]。
给完整配置步骤，必须带访问控制（ACL / 密码 / Access / IP 白名单）。
告诉我怎么确认没顺手暴露 SSH、数据库这些不该暴露的东西。
```

## Prompt ③ 隧道安全自查（每次用完跑）

```
生成"内网穿透安全自查清单"，每条是能逐条确认的动作：
- 有没有忘关的临时隧道（怎么查、怎么关）
- 开着的隧道有没有访问控制
- SSH / 数据库 / 后台有没有被暴露
- 长期访问是不是该换成 Tailscale
按 .vibe/launch.md「内网访问」段清单逐项确认勾选。
```

## 过关前自查

- 最容易出事的不是配错，是**开完忘了关**——现在有没有还开着的隧道？
- 管理后台走内网、产品页上公网：同一个产品可以两条线，别混
