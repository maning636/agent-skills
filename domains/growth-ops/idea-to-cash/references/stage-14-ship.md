# 第 14 关 · 上架收款

> 原理见《Vibe Coding》系列第 14 章 ｜ 产物: `.vibe/payment.md` ｜ 过关: `gate.mjs check 14`
> 上线 ≠ 上架：能收钱 = 一个能下单的落地页 + 一条真正跑通的支付链路。

## 陪跑流程

1. 用 ① 选一个**今天就能开张**的渠道（卖国内：小报童/知识星球；卖海外：Lemon Squeezy/Paddle/Gumroad——MoR 代缴税对个人是关键）。别用个人收款码、别在选型上纠结一周。
2. 用 ② 写卖货落地页（三块：价值主张/社会证明/单一 CTA；移动端优先；价格档位来自第 13 关，别再改）。
3. 用 ③ 生成链路自查清单并逐项确认——**最后一条"用真钱自己测一笔"gate 必查**，AI 列得再全也替代不了你真的去点一次。
4. 全部落 payment.md → `gate check 14`。

## Prompt ① 选收款渠道

```
帮我给产品选收款渠道并给接入步骤。
情况：卖给 [国内/海外] 用户；产品 <<注入 .vibe/vdf.md 的 V 段>>；
定价 <<注入 .vibe/pricing.md 的「模型与价格」段>>；我 [有/没有] 营业执照。
1. 推荐 1-2 个今天就能开张的渠道（结合手续费、是否 MoR 代缴税、个人能否开通）
2. 接入步骤和要准备的东西 3. 这个渠道的坑（额度/类目/到账周期/风控）
选定后写进 .vibe/payment.md「收款渠道」段。
```

## Prompt ② 卖货落地页

```
写产品落地页文案，按"价值主张 + 社会证明 + 单一 CTA"三块，移动端优先。
产品：<<注入 .vibe/vdf.md 的 V 段>>；价格：<<注入 .vibe/pricing.md 的「模型与价格」段>>
要求：主标题一句戳痛点、副标题一句具体好处（3 秒看懂）；
社会证明给占位框（放什么样的评价/前后对比最有说服力）；
全页只留一个 CTA，按钮文案给 2-3 个备选；不放导航菜单、不放第二个 offer。
定稿写进 payment.md「落地页三块」。
```

## Prompt ③ 支付链路自查

```
产品靠 <<注入 .vibe/payment.md 的「收款渠道」段>> 收款，交付方式 [下载/权限/激活码]。
生成"支付链路跑通"检查清单，覆盖：①钱真到账 ②付完立刻自动拿到东西 ③有退款口子 ④出问题找得到我。
每条写"我该亲自做什么来确认"；最后一条固定是：用真实小额钱在手机上自己走一遍全流程。
按 payment.md「支付链路四件事」逐项确认勾选。
```

## 过关前自查

- 真钱那一笔测了吗？付款页手机上跳没跳、付完立刻拿到货没有——只有真走一遍才知道
- 落地页只有一个 CTA 吗？多一个按钮少一成转化
