# MVP验证检查清单

> **用途**：在投入大量资源前，用最短时间、最小成本验证产品假设。

---

## 一、验证前准备（10项检查）

| # | 检查项 | 是否完成 | 备注 |
|:---:|:---|:---:|:---|
| 1 | 明确验证目标：要验证什么假设？ | ☐ | 例：用户愿意为AI生成的简历付费 |
| 2 | 定义成功标准：达到什么数据算验证成功？ | ☐ | 例：10人中有3人付费，转化率≥30% |
| 3 | 确定验证方法：手动/自动化/着陆页/访谈？ | ☐ | 选择最轻量的方式 |
| 4 | 明确目标用户：第一批测试用户从哪来？ | ☐ | 列出至少3个获客渠道 |
| 5 | 准备最小产品：能否在1周内做出来？ | ☐ | 可以是手动服务、Notion模板、微信群 |
| 6 | 设定时间盒：最多投入多少天/多少钱？ | ☐ | 建议：≤2周，≤1000元 |
| 7 | 准备数据记录工具：用什么记录用户行为？ | ☐ | 腾讯问卷、飞书多维表格、Excel |
| 8 | 准备用户反馈模板：问什么问题？ | ☐ | 见下方"用户访谈问题清单" |
| 9 | 团队对齐：所有人理解MVP范围吗？ | ☐ | 防止范围蔓延 |
| 10 | 设定止损线：什么情况下提前终止？ | ☐ | 例：3天0注册用户 |

### 用户访谈问题清单（验证前备用）

| 问题类型 | 问题示例 |
|:---|:---|
| 需求确认 | "你目前如何解决[这个问题]？每月花多少时间/多少钱？" |
| 痛点深挖 | "现有方案最让你头疼的地方是什么？" |
| 方案验证 | "如果我们提供[解决方案]，你会尝试吗？" |
| 付费验证 | "如果定价[X元]，你愿意现在预订吗？" |
| 推荐意愿 | "你会把这个推荐给有同样需求的朋友吗？" |

### Go/No-Go决策矩阵

| 维度 | 权重 | 评分（1-10） | 加权分 | 说明 |
|:---|:---:|:---:|:---:|:---|
| 数据是否达标 | 30% | | | 核心指标是否达到预设标准 |
| 用户反馈质量 | 25% | | | 反馈是否积极、是否有付费意愿表达 |
| 获客成本可控 | 20% | | | 单用户获取成本是否在预期内 |
| 执行过程顺利度 | 15% | | | MVP开发/运营是否比预期简单 |
| 团队信心度 | 10% | | | 团队是否愿意继续投入 |
| **总分** | 100% | — | **/10** | |

### 决策规则

| 总分 | 决策 | 下一步行动 |
|:---:|:---|:---|
| ≥ 7.5 | 🟢 **Go** | 制定正式产品计划，申请资源 |
| 5.0 - 7.4 | 🟡 **Pivot** | 调整方向/假设，进行第二轮验证 |
| < 5.0 | 🔴 **No-Go** | 放弃该方向，复盘经验，寻找新赛道 |

## 使用方法

1. **验证前**：逐项完成10项检查，确保MVP范围清晰。
2. **验证中**：每日填写记录表，每周回顾关键指标看板。
3. **验证后**：汇总数据，使用决策矩阵打分，做出Go/No-Go决定。
4. **无论结果**：完成复盘模板，沉淀经验。

## 填写说明

- **MVP要够轻**：能用微信群解决的不用小程序，能用手动解决的不用自动化。
- **成功标准要量化**：避免"用户很喜欢"这种模糊标准，要"3人付费"。
- **每日记录不过夜**：当天结束后10分钟内填写，避免遗忘。
- **诚实面对数据**：数据不达标时不要改标准，要改产品或方向。
