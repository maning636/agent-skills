# MVP 7天验证闭环（详细版）

## 核心理念

不是"产品做好了用户自然会来"，而是"先验证有没有人愿意付费，再决定投入多少"。

**关键指标**：不是"用户觉得好不好"，而是"愿不愿意掏钱"。哪怕只付¥99，也是真实需求。

## 7天流程

### Day 1-2：痛点确认

**目标**：找到10个目标用户，完成访谈

**行动**：
1. 列出你能接触到的10个潜在用户（前同事、朋友、行业群、社交媒体）
2. 准备访谈提纲（3个核心问题）：
   - 你目前在【某痛点】上是怎么解决的？
   - 每个月为此花多少钱/多少时间？
   - 如果有更好的方案，你愿意付多少钱？
3. 完成3-5个访谈，记录详细笔记

**通过标准**：≥5人确认有该痛点，且已在为该痛点付费

### Day 3-4：原型搭建

**目标**：用最低成本搭出可演示版本

**工具选择**：
- 非技术背景：Coze / Dify / 扣子（可视化搭建）
- 有代码基础：Cursor / V0 / Replit（AI辅助编程）
- 纯服务类：Notion / 飞书文档 + 视频演示

**原则**：
- 只做3个核心功能，其他全部砍掉
- 外观可以粗糙，核心流程必须跑通
- 3天内必须有一个"能点、能看、能演示"的东西

### Day 5-6：付费测试

**目标**：验证转化意愿

**话术模板**：
> "我做了个【产品名】，能帮你【解决什么问题】。现在正在找第一批测试用户，原价¥299，测试价¥99，限量10个。你需要吗？"

**关键动作**：
- 不要问"你觉得怎么样"，要问"你现在能付款吗"
- 如果对方犹豫，问"是什么让你犹豫？"
- 如果对方拒绝，问"什么样的产品你会愿意付费？"

**通过标准**：≥3人愿意付费（哪怕只是¥99）

### Day 7：决策点

| 结果 | 决策 |
|------|------|
| ≥3人付费 + 反馈积极 | 继续投入，进入正式开发 |
| 1-2人付费 | 优化方案，延长验证期2周 |
| 0人付费 | pivot 赛道或放弃 |

## 常见陷阱

1. **把"感兴趣"当"需求"**："挺有意思的"≠愿意付费
2. **原型过度设计**：3天的MVP不需要UI设计，能跑通就行
3. **只问朋友**：朋友会说好话，要找陌生人或弱关系
4. **定价太高**：测试期¥99-199即可，验证的是意愿不是价格敏感度
