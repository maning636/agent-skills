# 标准化交付 SOP

用于把 AI 服务从“靠个人发挥”变成“稳定可复制”。核心目标是减少返工、缩短交付周期、提高复购可能。

## 5 阶段交付法

| 阶段 | 目标 | 关键产物 |
|------|------|----------|
| 启动 | 对齐目标和边界 | 需求确认表、项目计划、素材清单 |
| 执行 | 按 SOP 产出 | 任务看板、AI产出、人工修订记录 |
| 内审 | 交付前发现问题 | 自检清单、质量评分、合规检查 |
| 交付 | 让客户会用 | 交付物、使用说明、下一步建议 |
| 复盘 | 沉淀案例和改进 | 满意度、案例授权、SOP更新 |

## 启动清单

- 明确交付目标：客户最终拿到什么。
- 明确不做什么：避免范围蔓延。
- 明确素材责任：客户需提供哪些资料、账号或数据。
- 明确沟通节奏：每几天同步一次进展。
- 明确验收标准：什么算完成，返工几次。

## 项目启动消息模板

```
本次项目目标：____
交付物：____
不包含：____
需要您提供：____
预计时间：____
沟通节奏：每____天同步一次
验收标准：____
修改次数：____
```

启动消息要在收款后立即发送，避免客户对范围和时间产生不同理解。

## 交付质量自检

| 检查项 | 问题 |
|--------|------|
| 目标一致 | 是否解决了客户最初确认的问题？ |
| 事实准确 | 数据、案例、引用是否可追溯？ |
| 品牌一致 | 语气、视觉、格式是否符合客户要求？ |
| 可执行 | 客户是否知道下一步怎么用？ |
| 合规风险 | 是否涉及版权、隐私、夸大承诺？ |

## 中间同步原则

客户最怕的不是慢，而是不知道进展。长于 7 天的项目至少每 3 天同步一次：

1. 已完成什么。
2. 下一步做什么。
3. 是否需要客户补充信息。
4. 是否存在风险或变更。

## 交付后动作

- 交付物最后附“使用指南”和“进阶服务建议”。
- 3-7天后发送验收和满意度调查。
- 14天后发送相关行业干货或优化建议。
- 30天后给续费、升级或复购方案。

## 案例沉淀模板

| 项目 | 内容 |
|------|------|
| 客户背景 | 行业、规模、典型痛点 |
| 问题 | 交付前的时间、成本或收入损失 |
| 方案 | 你做了什么，AI在哪些环节提效 |
| 结果 | 可量化结果或客户反馈 |
| 可公开程度 | 可实名/脱敏/仅内部 |

## 输出建议

当用户说“交付质量不稳定”时，先补启动清单和验收标准，再补 AI 工具和自动化。
