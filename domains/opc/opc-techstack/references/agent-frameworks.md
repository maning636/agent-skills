# Agent框架选型指南（2026版）

## 选型核心原则

**不是技术优劣，而是团队DNA匹配。**

- 过去三个月写过>500行代码 → LangChain/Dify
- 上次写代码在大学 → Coze/n8n

## 6大框架对比

| 框架 | 代码需求 | 学习曲线 | 部署方式 | 最佳场景 |
|------|---------|---------|---------|---------|
| **Coze（扣子）** | 零代码 | 极低 | 字节云服务 | 非技术创始人，1小时上手，微信生态 |
| **Dify** | 低代码 | 平缓 | 开源/云服务 | 快速上线AI应用，可视化编排 |
| **n8n** | 低代码 | 平缓 | 开源/云服务 | 连接SaaS生态，IFTTT进阶版 |
| **LangChain/LangGraph** | 中-高 | 陡峭 | 自托管/云 | 技术型创始人，需极致灵活 |
| **CrewAI** | 中 | 中等 | Python自托管 | 多角色Agent原型验证 |
| **AutoGen** | 高 | 陡峭 | 自托管 | 微软生态，复杂对话系统 |

## 按场景推荐

### 场景1：AI客服自动化

**推荐：Coze 或 Dify**

- Coze优势：原生微信/飞书集成，1小时搭完
- Dify优势：更灵活的知识库管理，支持多模型切换

**核心配置**：
- 知识库：上传FAQ文档+产品手册
- 意图识别：设置20-30个常见意图
- 转人工：置信度<0.7时自动转接
- 统计：记录每个问题的解决率

### 场景2：内容生产自动化

**推荐：n8n + GPT API**

工作流示例：
```
选题库(Google Sheets) → AI生成初稿 → 人工审核 → 自动发布到多平台
```

### 场景3：数据分析自动化

**推荐：LangChain + Python**

- 连接数据库（SQL Agent）
- 自动生成图表（Matplotlib/Plotly）
- 生成分析报告（结构化输出）

## MCP/A2A协议应用

### MCP（Model Context Protocol）

AI模型与外部工具的"USB-C"接口。

**实践场景**：
- 连接公司数据库 → Agent自动查数据
- 连接邮箱API → Agent自动发报告
- 连接日历API → Agent自动预约会议

**配置示例**：
```json
{
  "mcpServers": {
    "database": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres"],
      "env": { "DATABASE_URL": "postgresql://..." }
    }
  }
}
```

### A2A（Agent-to-Agent）

多Agent协作通信标准。

**实践场景**：
- 客服Agent处理不了的 → 转技术Agent
- 内容Agent产出后 → 质检Agent审核
- 销售Agent签约后 → 交付Agent启动
