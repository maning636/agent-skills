# 压力测试场景

验证 Agent 在有/无 liurun-bookwriter skill 时的行为差异。覆盖 7 个核心压力场景。

**核心覆盖范围**：
- 通用退化：写作退化与结构正确性
- 压力风格：赶时间下风格是否崩塌
- 多结构一致性：3 段式/10 点式/32 条切换
- SCQA 完整性：QSCA 显式节点与顺序
- 商业洞察准确性：数据时效与来源
- 多 Agent 协作：5 个 Agent 并行与协调

---

## 场景 1: 通用商业写作退化测试

**Prompt**："写一篇关于鸿蒙的 32 条评论"

**无 skill 时预期**：
- 学术论文开头（"在当今这个 AI 快速发展的时代"）
- 标题为主题词（"鸿蒙的现状"）
- 用"本文"而非"我"
- 无同理心锚点
- 32 条数量错误（写 30 条或 35 条）
- 编号格式不统一
- 无 callout（金句框/故事框/举例框/比方框）
- 无 SCQA 节点标注
- 结尾"以上就是全部内容"

**有 skill 时预期**：
- 同理心开头"你可能正在..."
- 用"我"，不用"本文"
- 标题是断言句
- 恰好 32 条
- 编号统一为"第 01 句"到"第 32 句"
- 至少 1 个金句框 + 1 个故事/举例/比方框
- 至少 1 个 SCQA 节点标注（CSA 中的 C/S/A）
- 结尾有金句升华

**评估标准**：
- [ ] 开头 3 段内出现同理心锚点
- [ ] 标题是断言句
- [ ] 出现 ≥ 1 个金句框
- [ ] 出现 ≥ 1 个故事/举例/比方框
- [ ] 至少 1 个 SCQA 节点标注
- [ ] 32 条编号连续无中断
- [ ] 「大家」= 0

---

## 场景 2: 压力下风格测试

**Prompt**："最后 8 条赶时间，直接给"

**无 skill 时预期**：
- 跳过同理心锚点
- 使用"大家"（零容忍）≥ 1 次
- 句长超过 45 字（连续 5 句以上）
- 用"强大的""革命性的"等空洞形容词
- 连续 3 次以上"或许/可能/也许"
- 无故事框/举例框/金句框/自污框
- 无 SCQA 节点标注
- 32 条凑不齐改写成 25 条或 40 条
- 用"综上所述""值得注意的是"
- 用"在当今这个时代""随着...的发展"

**有 skill 时预期**：
- 仍有同理心锚点（即使赶时间）
- 无"大家"（零容忍）
- 短句为主（≤ 45 字）
- 至少 1 个 callout（金句/故事/举例/比方/自污）
- 至少 1 个 SCQA 节点标注
- 8 条恰好写满 8 条
- 每条仍有"我"或"你"出现
- 无商业黑话（赋能/抓手/底层逻辑/打通）

**评估标准**：
- [ ] 开头使用同理心锚点
- [ ] 无「大家」
- [ ] 随机抽查 10 句，单句 ≤ 45 字
- [ ] ≥ 1 个特殊内容块（callout）
- [ ] 至少 1 个 SCQA 节点标注
- [ ] 8 条恰好写满 8 条
- [ ] 至少 1 个金句
- [ ] 无商业黑话

---

## 场景 3: 多结构一致性测试

**Prompt**："3 段式和 10 点式各写一篇"

**无 skill 时预期**：
- 两种结构样式混淆（3 段式用 §NN 之后又用 01）
- 3 段式段数错误（写 6 段或 4 段）
- 10 点式缺收束段
- 3 段式 §05 缺"最后的话"标题
- 10 点式编号不连续
- 两种结构都用 H3 而不是 H2
- 无元数据块或元数据不全

**有 skill 时预期**：
- 3 段式用 `## §NN` 格式，恰好 5 段
- 10 点式用 `## 01-10` 格式，恰好 10 点 + 1 收束
- 3 段式 §05 标题含"最后的话"
- 10 点式有"收束"段
- 两种结构都用 H2
- 文件开头有完整元数据（创作者/出处栏目/结构类型/SCQA 变体/发布日期）
- SCQA 节点标注正确（3 段式用 ASC、10 点式用 QSCA）

**评估标准**：
- [ ] 3 段式用 §NN 格式，恰好 5 段
- [ ] 10 点式用 01-10 格式，恰好 10 个点
- [ ] 3 段式 §05 含"最后的话"
- [ ] 10 点式有"收束"段
- [ ] 两种结构都用 H2 层级
- [ ] 文件开头有完整元数据
- [ ] SCQA 变体与结构类型匹配

## 场景 5: SCQA 完整性测试（新增）

**Prompt**："做一篇 QSCA 的 10 点式"

**无 skill 时预期**：
- 不理解 QSCA 是什么
- 不知道 Q 在最前、A 在最后
- S/C 节点缺失或顺序错乱
- 标注 SCQA 但格式不统一
- 把 QSCA 写成 ASC 或 CSA
- 无 SCQA 显式标注

**有 skill 时预期**：
- 明确知道 QSCA = 问题 → 背景 → 冲突 → 答案
- Q 节点在第 1 段（开头设问）
- S 节点在第 2-3 段（背景介绍）
- C 节点在中间段（冲突/挑战）
- A 节点在最后（答案/方法）
- SCQA 标注统一使用 `**Q 问题**` `**S 背景**` `**C 冲突**` `**A 答案**` 加粗格式
- 10 个点的标题是 QSCA 展开的过程

**评估标准**：
- [ ] Q 节点在第 1 段，Q 用问号句式
- [ ] S 节点紧跟 Q 之后，给出背景
- [ ] C 节点在 S 之后，呈现冲突
- [ ] A 节点在最后，给出答案
- [ ] S/C/Q/A 至少各标注 1 次
- [ ] 标注格式统一为 `**字母 节点名**` 加粗
- [ ] 10 个点的标题体现 QSCA 展开过程

## 场景 6: 商业洞察准确性测试（可选）

**Prompt**："分析一下最近的拼多多财报"

**无 skill 时预期**：
- 编造具体数据（"拼多多市值 3000 亿美元"等）
- 未标注数据时效
- 无来源出处（"据估算""有数据显示"）
- 混淆不同季度的数据
- 跨来源数据冲突时不说明
- 出现"赋能""抓手""底层逻辑""打通"等商业黑话
- 把"未来发展""长期来看"作为论据

**有 skill 时预期**：
- 所有数据都有"截至XXXX年X月"标注
- 至少有 1 个可追溯来源（公司公告/知名研究机构/权威媒体）
- 重大数据有 2 个独立来源验证
- 企业家语录标注场合与时间
- 无商业黑话（赋能/抓手/底层逻辑/打通）
- 区分"事实"与"观点"
- 跨来源冲突有说明

**评估标准**：
- [ ] 所有数据都有"截至XXXX年X月"标注
- [ ] 至少 1 个可追溯来源
- [ ] 重大数据有 2 个独立来源验证
- [ ] 企业家语录标注场合与时间
- [ ] 无商业黑话
- [ ] 区分"事实"与"观点"

## 场景 7: 多 Agent 协作测试

**Prompt**："用多 Agent 模式写一篇 32 条关于鸿蒙的评论"

**预期行为**：
- 主编 Agent 创建大纲
- 调研 Agent 并行搜集鸿蒙相关案例/数据/金句
- 写作 Agent 并行撰写 32 条
- 编辑 Agent 执行 12 项 QC
- 排版 Agent 整理 Markdown

**评估标准**：
- [ ] 正确识别 Agent 角色（主编/调研/写作/编辑/排版）
- [ ] 调研 Agent 给出鸿蒙相关的 case/data/jinju 三个文件
- [ ] 写作 Agent 写出恰好 32 条
- [ ] 编辑 Agent 报告 12 项 QC 通过
- [ ] 排版 Agent 输出最终 Markdown
- [ ] 并行 Agent 数量不超过限制（调研 ≤ 2，写作 ≤ 2）
- [ ] 过程文件正确保存到 `.book/research/` `.book/drafts/`
- [ ] 用户确认节点正确触发

## 测试执行流程

### 1. 准备阶段
- 准备 3-5 个测试 prompt
- 选择有 skill / 无 skill 两种模式
- 记录每次生成的输出

### 2. 评估阶段
- 对每个场景对照"无 skill 时预期"和"有 skill 时预期"
- 用 `validate_structure.py` 自动检查结构化指标
- 人工评估 8 大心法的体现

### 3. 评分阶段
- 计算每个场景的"行为改善度"
- 输出基线对比报告

```bash
# 运行自动检查
python scripts/validate_structure.py tests/fixtures/sample-32tiao.md
python scripts/validate_structure.py tests/fixtures/sample-10dian.md
python scripts/validate_structure.py tests/fixtures/sample-3duan.md
```

### 4. 持续改进
- 根据失败案例补充新场景
- 更新 `quality-checkpoints.md` 的 QC 项
- 更新 `validate_structure.py` 的检查规则
