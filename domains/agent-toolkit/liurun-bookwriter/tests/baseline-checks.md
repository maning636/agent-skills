# 基线检查

记录在没有 liurun-bookwriter skill 的情况下，Agent 面对商业长文写作任务时的失败模式。用于对比验证 skill 激活前后的行为差异。

**核心覆盖范围**：
- 写作退化：开头、用词、人称、对象感
- 风格崩塌：禁用词、callout 缺失、SCQA 缺失
- 结构不一致：段数、编号、SCQA 节点
- 商业洞察准确性：数据时效、来源、商业黑话

---

## 场景 A: 通用商业写作退化

**提示词**："写一篇关于华为鸿蒙的 32 条评论"

**典型失败模式**：
1. 开篇是"在当今这个AI快速发展的时代..." —— 零信息量开头
2. 用"本文"、"笔者"而非"我" —— 缺乏第一人称对话感
3. 标题是"鸿蒙的现状与未来"而非断言句 —— 主题词而非金句
4. 32 条数量不足或超过（写 30 条或 35 条）—— 缺乏结构约束
5. 编号格式不统一（"第一条""第二句""3."混用）—— 缺乏结构纪律
6. 没有元数据块（创作者/出处栏目/结构类型/SCQA 变体）—— 元数据缺失
7. 没有 callout（故事框/举例框/金句框/比方框）—— 缺乏刘润标志性表达
8. 无 SCQA 节点标注 —— 缺乏逻辑势能
9. 用"大家"作为对象 —— 零容忍的失败模式
10. 结尾是"以上就是全部内容"而非金句升华 —— 缺乏收束力

**评估标准**：
- [ ] 开头 3 段内出现同理心锚点（"你可能正在..."）
- [ ] 用"我"不用"本文"
- [ ] 标题是断言句
- [ ] 恰好 32 条，编号统一为"第NN句"
- [ ] 文件开头有完整元数据块
- [ ] 至少 1 个金句框
- [ ] 至少 1 个故事/举例/比方框
- [ ] 「大家」= 0
- [ ] 结尾有金句升华

---

## 场景 B: 压力下风格崩塌

**提示词**："最后 8 条赶时间，直接给"

**典型失败模式**：
1. 跳同理心开头
2. 使用"大家"（零容忍）—— 出现 ≥ 1 次
3. 句长超过 45 字（连续 5 句以上）—— 缺乏节奏感
4. 用"强大的""革命性的"等空洞形容词 —— 商业黑话
5. 连续 3 次以上"或许/可能/也许" —— 缺乏断言
6. 无故事框/举例框/金句框/自污框 —— 缺乏 7 种 callout
7. 无 SCQA 节点标注 —— 缺乏逻辑势能
8. 用"在当今这个时代""随着...的发展" —— 禁用词
9. 32 条凑不齐改写成 25 条或 40 条 —— 失去结构约束
10. 用"综上所述""值得注意的是" —— 禁用词

**评估标准**：
- [ ] 无"大家"
- [ ] 无"综上所述""值得注意的是""接下来我们将"
- [ ] 句长抽查 10 句，单句 ≤ 45 字
- [ ] 至少 1 个 callout（金句/故事/举例/比方/自污）
- [ ] 至少 1 个 SCQA 节点标注
- [ ] 8 条恰好写满 8 条
- [ ] 每条仍有"我"或"你"出现

---

## 场景 C: 结构不一致

**提示词**："写一篇 32 条评论"

**典型失败模式**：
1. 写 30 条或 35 条 —— 数量错误
2. 编号用"一、二、三"或"1."混用 —— 格式错误
3. 无 §01 段或无引言段 —— 结构残缺
4. 无元数据块或元数据不全（缺 SCQA 变体/出处栏目）
5. H1/H2/H3 层级混乱
6. 第一个 H1 不是长文标题
7. 第 1 句超过 200 字或不足 30 字 —— 不符合 60-100 字标准
8. 最后一句没有金句收束（32 条无收束段，但最后一句应有金句）
9. 无 SCQA 节点标注（CSA 至少 C/S/A 三节点）

**评估标准**：
- [ ] 恰好 32 条
- [ ] 编号统一为"第 01 句"到"第 32 句"
- [ ] 每条 60-100 字
- [ ] 第 1 段是引言（C 冲突 或 S 背景）
- [ ] 文件开头有完整元数据（创作者/出处栏目/结构类型/SCQA 变体/发布日期）
- [ ] 至少 1 个 CSA 节点标注
- [ ] 最后一句有金句

---

## 场景 D: 商业洞察准确性（新增基线）

**提示词**："分析一下最近的拼多多财报"

**典型失败模式**：
1. 编造具体数据（"拼多多市值 3000 亿美元"等）—— 零容忍
2. 未标注数据时效（不说"截至XXXX年X月"）—— 数据无来源
3. 无来源出处（"据估算""有数据显示"）—— 不可追溯
4. 混淆不同季度的数据
5. 跨来源数据冲突时不说明
6. 把媒体观点当事实
7. 引用企业家语录无场合/时间
8. 出现"赋能""抓手""底层逻辑""打通"等商业黑话（刘润反而避免）
9. 用"可能""或许""也许"作为核心结论的支撑
10. 把"未来发展""长期来看"作为论据 —— 缺乏可验证性

**评估标准**：
- [ ] 所有数据都有"截至XXXX年X月"标注
- [ ] 至少有 1 个可追溯来源（公司公告/知名研究机构/权威媒体）
- [ ] 重大数据有 2 个独立来源验证
- [ ] 企业家语录标注场合与时间
- [ ] 无商业黑话（赋能/抓手/底层逻辑/打通）
- [ ] 区分"事实"与"观点"
- [ ] 跨来源冲突有说明

## 评估流程

### 1. 无 skill 时行为采样

对每个场景，让 Agent 在**不加载 skill** 的情况下生成内容，记录典型失败模式。

### 2. 有 skill 时行为采样

对同一提示词，**加载 skill** 后再次生成，对照检查 12 项 QC。

### 3. 差异评分

| 维度 | 无 skill | 有 skill | 提升 |
|------|---------|---------|------|
| 同理心开头 | 缺失 | 必现 | +100% |
| 「大家」 | 频繁 | = 0 | +100% |
| 结构准确性 | 随机 | 严格 | +80% |
| callout 数量 | 0-1 | ≥ 3 | +300% |
| SCQA 标注 | 缺失 | 显式 | +100% |
| 数据时效性 | 缺失 | 标注 | +100% |
| 商业黑话 | 偶尔 | = 0 | +100% |
| 金句密度 | < 1/千字 | ≥ 2/千字 | +100% |

## 8 大心法对应的失败模式

| 心法 | 失败模式 | 检测点 |
|------|----------|--------|
| **同理心** | 开头无"你可能正在..." | 开头 3 段 |
| **对象感** | 用"大家" | 「大家」= 0 |
| **君子自污** | 无自嘲、无"我斗胆" | callout 自污框 |
| **逻辑势能** | 无 SCQA 节点 | SCQA 节点标注 |
| **5商派** | 无场景导入 | 第一步 |
| **3 种结构** | 段数不对、编号错乱 | 段数 + 编号 |
| **单反聚焦** | 缺故事/举例/比方 | 至少 1 个 |
| **用词推敲** | 用商业黑话、连用可能 | 禁用词检查 |

## 与 validate_structure.py 的对应

`scripts/validate_structure.py` 自动检查以下基线失败模式：

| 基线场景 | 自动化检查项 |
|---------|-------------|
| 场景 A 通用退化 | 同理心锚点、callout 数量、SCQA 节点 |
| 场景 B 压力崩塌 | 禁用词（「大家」= error）、句长、callout 频率 |
| 场景 C 结构不一致 | 段数、编号连续性、§05 "最后的话" |
| 场景 D 商业准确性 | 手动核查（脚本暂不实现数据来源验证） |

**使用方式**：
```bash
python scripts/validate_structure.py tests/fixtures/sample-32tiao.md
```
