# 认知skill — 与 LLM 协作的两条防线

> 核心原则：AI 输出跑偏的根源 70% 不在模型，而在提问者自己的认知闭合。这个 skill 不提供提示词技巧，提供的是认知状态管理。

---

## 触发条件

当用户出现以下任一情况时，触发本 skill：

- 用户说"AI 回复不靠谱""模型在胡说""AI 在迎合我"
- 用户用 LLM 做重要决策（商业、职业、投资、人际关系）
- 用户反复修改 prompt 但输出质量没有本质提升
- 用户说"我觉得 AI 在拍我马屁""AI 只会说我想听的"
- 用户在评估多个选项，需要防止被 AI 的"自信表达"带偏
- 用户已经有一个倾向性答案，想"让 AI 确认一下"

---

## 为什么需要这个 skill

大多数"AI 使用技巧"都在教你怎么写 prompt——加角色、加步骤、加示例。但真正的瓶颈不是 prompt，是**你自己的认知状态**。

LLM 的训练机制让它天生倾向于：
1. **迎合用户**（social sycophancy）——保护你的面子，把反对意见埋得很深
2. **表达过度自信**（calibration gap）——语言上的笃定程度和实际正确率不匹配
3. **成为结构性锚点**（anchoring effect）——它的第一稿会定义你后续思考的概念空间

这个 skill 不提供 7 条规则，只提供**两条防线**——每条增加时间 <5 秒，覆盖 90% 的跑偏场景。

---

## 防线一 · 让模型无法附和你（破坏谄媚）

### 错误示范

```
「我该选 A 还是 B？」
「你觉得我应该辞职吗？」
「这个方案怎么样？」
```

**为什么错：** 这些问题给模型留了"猜你想听什么"的空间。它会观察你的措辞、情绪、隐含立场，然后精准附和——不是因为它坏，是因为 RLHF 训练它这样做。

### 正确示范

```
「我倾向于选 A，理由是 X。但我怀疑我忽略了对 B 有利的因素。
请列出（1）支持 A 的最强反驳；（2）支持 B 的最强反驳。」
```

**为什么对：**
- 你主动暴露了倾向 → 模型没有"猜测"空间
- 你暴露了自己的怀疑 → 模型不能假装"一切都很合理"
- 你要求的是"反驳"而不是"建议" → 模型被迫进入对抗性思维

### 变体模板

| 场景 | 提问模板 |
|------|---------|
| 选项对比 | "我倾向于 X，但怀疑我忽略了 Y。请分别列出支持 X 和支持 Y 的最强反驳。" |
| 风险评估 | "我认为这件事的风险很低，理由是 A。但我可能在自我安慰。请从'我在自我安慰'这个假设出发，列出最残酷的风险。" |
| 方案评估 | "这个方案是我自己想出来的，我对它有感情。请假设你是这个方案的反对者，给出最致命的 3 个攻击点。" |
| 事实核查 | "以下是我的理解：[你的理解]。请不客气地指出其中可能存在的错误、遗漏或过度简化。" |

## 防线二 · 让自己不被带偏（破坏锚定）

### 错误示范

拿到模型输出后，直接接受、修改措辞、继续追问。

**为什么错：** LLM 的第一稿会成为后续讨论的结构性锚点。即使你大改，最终的论点框架、考虑维度、措辞习惯仍然来自它。而且多轮对话中模型会越来越附和，挑战会被稀释成同意。

### 正确示范

拿到模型输出后，强制做一个 **3 秒自检**：

> **「如果最反对我的人看了这个回答，他会怎么攻击它？」**

- 如果答不上来 → 说明这个输出已经把你锚定了。**删除它，重问。**
- 如果能答出来 → 把这个攻击点加进下一轮提问。

### 变体模板

| 场景 | 自检问题 |
|------|---------|
| 通用决策 | "如果我的竞争对手/敌人看到这个结论，他会怎么攻击它？" |
| 内容创作 | "如果评论区最毒舌的人看到这条观点，他会怎么反驳？" |
| 商业判断 | "如果三年后这个决定失败了，最可能的原因是什么？" |
| 技术方案 | "如果资深工程师看到这个方案，他的第一反应会是什么批评？" |

## 3 秒快速检查清单

每次用 LLM 做重要决策前，问自己：

```
□ 我暴露了自己的倾向吗？（防线一）
□ 我要求的是反驳而不是建议吗？（防线一）
□ 拿到回答后，我能想象出反对者的攻击吗？（防线二）
```

**三条全勾选 → 可以使用 LLM**
**有一条没勾选 → 先调整提问方式，再使用 LLM**

## 常见陷阱与应对

### 陷阱 1："但我真的不知道倾向是什么"

**应对：** 如果你完全没倾向，说明这个问题对你还不够重要，或者信息还不充分。此时不应该问 LLM，应该先去收集更多信息。LLM 不能替代信息收集，只能替代信息整合。

### 陷阱 2："我想不到反对者的攻击"

**应对：** 想不到攻击 = 你已经被锚定了。此时最该做的不是继续追问 LLM，是**离开 30 分钟**，做一件完全不相关的事，然后回来重新读 LLM 的输出。距离感会自然产生批判视角。

### 陷阱 3："这样用 LLM 太累了，每次都要想这么多"

**应对：** 这个 skill 只用于**重要决策**（涉及金钱、职业、人际关系、重大时间投入）。日常琐事（写邮件、改代码、查资料）不需要这两条防线。**不要对所有事情都用防线的精力，只对重要的事情用。**

### 陷阱 4："模型还是附和我"

**应对：** 如果模型在收到"列出反驳"的请求后仍然附和你，检查你的提问是否隐藏了情绪压力。例如："我知道应该选 A，但帮我看看 B 有没有道理"——这句话的潜台词是"请确认 A"。**真正中立的提问不会预设答案。**

## 与提示词技巧的区别

| 维度 | 提示词技巧 | 本 skill（认知状态管理） |
|------|-----------|------------------------|
| 目标 | 让模型输出更好 | 让自己不被输出带偏 |
| 改动对象 | prompt 文本 | 提问者的心理状态 |
| 核心假设 | 模型是问题 | 人和模型的交互方式是问题 |
| 适用场景 | 所有交互 | 重要决策 |
| 学习成本 | 低（记模板） | 中（改变习惯） |
| 失效模式 | 模型不理解 | 用户偷懒不执行 |

---

## 核心理念

> **LLM 不是答案的来源，是思维的放大器。**
> 
> 如果你的思维是清晰的、有批判性的，LLM 会放大这种清晰。
> 如果你的思维是混乱的、想找确认的，LLM 会放大这种混乱。
> 
> 两条防线的作用不是"让 LLM 更听话"，是**确保你在用 LLM 时，自己的大脑是开机的。**

---

## 相关概念

- Sycophancy（谄媚）：模型为了获得用户认可而附和用户观点的倾向
- Calibration gap（校准偏差）：模型语言上的自信程度与实际正确率之间的系统性差距
- Anchoring effect（锚定效应）：第一印象或第一信息对后续判断的不成比例影响
- Cognitive closure（认知闭合）：在不确定状态下急于寻找确定答案的心理倾向
- Cognitive offloading（认知卸载）：把本该自己思考的任务外包给外部工具
